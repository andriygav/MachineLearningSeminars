## Как работать и что сдавать

Задание состоит из двух частей: реализация полносвязной сети на NumPy и исследование её обучения на двумерной классификации. Решение первой части нужно для второй. Выполнять задание необходимо в этом же ipynb файле, заполняя отведённые ячейки (можно добавлять новые).

1. Перед опытами **2.2, 2.3 и 2.4** запишите гипотезу одной или несколькими фразами.
2. Выполните опыт и объясните наблюдения. Обычно достаточно 2–4 предложений на практический подпункт; для 2.4 и 2.5 можно немного больше. Отвечать связным человеческим текстом, можно без переписывания вопросов. Не надо пытаться генерить этот текст, запишите от себя результаты наблюдений, можно коротко и своими словами. **Нейрослоп текст в этом месте будет приравниваться к невыполнению задания.**
3. Если ожидание не подтвердилось, объясните результат. Не меняйте данные ради удобного вывода, это не влияет на оценивание.
4. Сдайте один `.ipynb` с кодом, результатами и ответами. Отдельный отчёт не нужен.
5. Перед сдачей выполните **Restart Kernel → Run All**. Ноутбук должен работать сверху вниз. Все предоставленные проверки должны завершиться со статусом `OK`.

Работу удобно разделить на два подхода: сначала задание 1, затем задание 2.

| Часть | Содержание |
| --- | --- |
| 1.1. Линейный слой и ReLU | `forward` / `backward` |
| 1.2. Композиция и функция потерь | `Sequential`, softmax-кросс-энтропия |
| 1.3. Оптимизатор и цикл обучения | `SGD`, `fit` |
| 1.4. Проверка корректности | Свой тест и обучение на 16 объектах |
| 2.1. Данные и предобработка | Описание наборов и baseline |
| 2.2. Линейная модель и сеть | Сравнение на `clouds` и `circles` |
| 2.3. Ширина и шаг обучения | Две серии на `circles` |
| 2.4. Активация и скрытый слой | ReLU против `Step` |
| 2.5. Итоговая оценка | Одна фиксация, затем test |

В реализации оцениваются корректность кода и прохождение проверок. В исследовании — согласованность запусков, таблицы, графики и объяснение наблюдений. Частично выполненные пункты получают частичный балл. Графикам достаточно подписанных осей и понятной легенды; декоративное оформление не оценивается. Заданного порога accuracy нет.

Слои, аналитические градиенты, оптимизатор и цикл обучения реализуйте самостоятельно. Автоматическое дифференцирование и готовые нейросетевые модели использовать нельзя. Численное дифференцирование допускается только при проверке градиентов. Сигнатуры методов и предоставленные проверки сохраняйте.

**Разбиение данных.** Для каждого набора заранее выделены три части:

- `train` — для обучения моделей и предобработки;
- `validation` — для сравнения конфигураций и обоснования выбранных настроек;
- `test` — только в пункте 2.5, после фиксации архитектуры, предобработки и режима обучения.

Во всех сравнениях сохраняйте выбранную предобработку, число эпох и размер батча; если не оговорено иное, меняйте только исследуемый параметр. Каждый запуск начинается с исходной инициализации. После выбора модели не переобучайте её на train + validation. «Один раз на test» означает финальную оценку зафиксированного решения: повторный запуск всего ноутбука перед сдачей допустим, подбор по test — нет.

**Места для работы.** Пишите решения в пустых кодовых ячейках и текстовых ячейках «Ответ», «Гипотеза», «Обсуждение результатов»; при необходимости добавляйте свои ячейки. Предоставленные генерацию данных, разбиение, `evaluate`, `plot_boundary` и служебные функции можно использовать без изменений.
