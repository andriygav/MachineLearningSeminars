## Как работать и что сдавать

Задание состоит из 4 задач - 2 теоретические и 2 практические. Решение теоретических поможет при решении практических. Выполнять задание необходимо в этом же ipynb файле заполняя отведённые ячейки (можно добавлять новые).

1. Перед опытами **3.3, 3.4, 4.3 и 4.4** запишите ожидаемый эффект одной фразой.
2. Выполните опыт и объясните наблюдения. Обычно достаточно 2–4 предложений на практический подпункт; для 3.4 и 4.2 можно немного больше. Отвечать связным человеческим текстом, можно без переписывания вопросов. Не надо пытаться генерить этот текст, запишите от себя результаты наблюдений, можно коротко и своими словами. **Нейрослоп текст в этом месте будет приравниваться к невыполнению задания.**
3. Если ожидание не подтвердилось, объясните результат. Не меняйте данные ради удобного вывода, это не влияет на оценивание.
4. Сдайте один `.ipynb` с кодом, результатами и ответами. Отдельный отчёт не нужен.
5. Перед сдачей выполните **Restart Kernel → Run All**. Ноутбук должен работать сверху вниз.

Работу удобно разделить на два подхода: задачи 1 и 3, затем 2 и 4.

| Часть | Баллы |
| --- | ---: |
| 1. Теория регуляризации | 20 |
| 2. Метрики и порог | 15 |
| 3. Эксперименты с регрессией | 30 |
| 4. Эксперименты с классификацией | 30 |
| Итоговые выводы | 5 |
| **Всего** | **100** |

В теории оцениваются верность ответа и обоснование. В каждой практической
задаче 18 баллов отводятся корректности обучения, расчётов и графиков,
12 — объяснению наблюдений. Частично выполненные пункты получают частичный балл.
Графикам достаточно подписанных осей и понятной легенды; декоративное оформление
не оценивается. Заданного качества модели достигать не требуется.

**Разбиение данных.** В каждой практической задаче заранее выделены три части:

- `train` — для обучения моделей и предобработки;
- `validation` — для сравнения поведения моделей и обоснования выбранных настроек;
- `test` — для одной финальной проверки после фиксации модели и её настроек.

Масштабирование обучается только на train; к validation и test применяется уже обученное преобразование.
`Pipeline` объединяет предобработку и модель, чтобы применять их согласованно.
Во всех опытах сохраняйте исходное разбиение. Выводы относятся к этому разбиению;
небольшая разница ошибок не доказывает превосходства алгоритма на любых данных.
После выбора модели используйте её без переобучения на train + validation.
«Один раз на test» означает финальную оценку зафиксированного решения:
повторный запуск всего ноутбука перед сдачей допустим, подбор по test — нет.

**Места для работы.** Пишите решения в пустых кодовых ячейках и текстовых ячейках «Ваш ответ»;
при необходимости добавляйте свои ячейки. В теории запишите решения текстом с формулами.
Предоставленные загрузку данных, разбиения и служебные функции можно использовать без изменений.
В практике готовые импорты имеют префиксы `reg_` и `cls_`;
можно пользоваться ими или добавить обычные импорты самостоятельно.
